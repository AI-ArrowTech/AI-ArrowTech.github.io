Case 04 · Applied AI

Designing an agent around trust.

A local-first architecture kept memory, retrieval and routine work close to the user while reserving cloud models for tasks that genuinely needed them.

The situation

A useful personal AI system needs context: files, preferences, history and access to tools. Sending every task and every memory to a remote model created unnecessary cost, latency and exposure. Keeping everything local, however, limited the quality available for complex reasoning and research.

The design question was not “local or cloud?” It was how to place each responsibility where its trade-offs made sense.

Trust emerges from boundaries users can understand—not from a single model choice.

What we designed

The reference architecture separated channels, orchestration, memory, retrieval, tools and models. A gateway classified work by sensitivity and capability needs, then routed it through a local path or a controlled cloud escalation.

Core layers

  • Channel adapters that normalized requests without coupling the agent to one interface.
  • An orchestration layer for tool use, task state and policy enforcement.
  • Local memory and retrieval for durable, user-controlled context.
  • Caching and refinement for repeatable work and reduced model spend.
  • Selective fallback to cloud models for higher-order reasoning and research.

Critical design choices

Route by task and sensitivityModel selection followed policy, context and required capability.
Keep memory independentDurable context belonged to the system, not a specific model provider.
Make tool access explicitPermissions and credentials were scoped at the tool boundary.
Design graceful fallbackUnavailable services reduced capability without collapsing the experience.

The impact

The architecture created a practical balance between privacy, cost and frontier capability. It provided a path for starting small on local hardware while retaining the option to escalate selectively—and made those decisions governable instead of accidental.

What this case demonstrates

Responsible AI architecture is less about choosing one model and more about designing boundaries: where context lives, how tools are authorized, when data leaves the device and what happens when a dependency fails.
